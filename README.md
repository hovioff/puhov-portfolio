# Портфолио работ

Мобильный каталог работ: блоки проектов, отдельная страница каждого кейса и админка. По умолчанию админка сохраняет данные локально. Для общего облачного хранилища настроен Supabase.

Запуск из этой папки: `python3 -m http.server 8000`, затем откройте `http://localhost:8000`.

- `index.html` — только каталог работ и фильтры.
- `project.html?id=meatbone` — отдельный адрес страницы проекта.
- `admin.html` — добавление и редактирование проектов, дат, сроков и слайдов.
- `styles.css` — общий дизайн.
- `js/` — каталог, данные и поведение страниц.
- `js/supabase-config.js` — отдельный файл с URL проекта и публичным ключом Supabase.
- `supabase/schema.sql` — таблица, доступы и файловое хранилище.
- `assets/meatbone/` — пять слайдов из исходного файла.

## Подключение Supabase

1. Создайте бесплатный проект Supabase и выполните `supabase/schema.sql` в разделе SQL Editor.
2. В `js/supabase-config.js` заполните Project URL и Publishable key (или старый anon key) из Project Settings → API Keys.
3. В настройках Auth отключите публичную регистрацию и добавьте своего пользователя через Supabase Dashboard → Authentication → Users. Вход в `admin.html` будет доступен только созданным пользователям.
4. Опубликуйте эти файлы на GitHub Pages и войдите в админку. Изменения проектов и слайды будут сохраняться в Supabase.

Ключ в конфиге является публичным ключом браузера, поэтому права ограничены политиками RLS из SQL-файла. Secret/service_role key нельзя публиковать в GitHub или добавлять в браузерный код. Пока конфиг пустой, сайт продолжает работать в локальном режиме на IndexedDB.
