# Портфолио работ

Мобильный каталог проектов с отдельными страницами кейсов и админкой.

## Как открыть локально

Из этой папки запусти `python3 -m http.server 8000` и открой `http://localhost:8000`.

- `index.html` — каталог работ.
- `project.html?id=meatbone` — отдельная страница проекта.
- `admin.html` — создание и редактирование проектов.
- `styles.css` и `js/` — оформление и поведение страниц.

Пока файл настроек Supabase не заполнен, админка хранит данные в этом браузере.

## Подключение Supabase — пошагово

### 1. Создай проект

Зайди на [supabase.com/dashboard](https://supabase.com/dashboard), создай организацию, если Supabase попросит, затем нажми **New project**. Придумай имя проекта и пароль базы данных. Пароль базы сохрани отдельно: в сайт его вставлять не нужно.

### 2. Создай таблицу и хранилище одним запуском SQL

1. Открой свой проект Supabase.
2. В левом меню выбери **SQL Editor** → **New query**.
3. Открой в папке сайта `supabase/schema.sql`, скопируй весь файл и вставь в окно запроса.
4. Нажми **Run**. Скрипт создаст таблицу портфолио, доступ для чтения сайта, правила записи только для вошедшего пользователя и публичное хранилище картинок `portfolio-slides`.

Повторный запуск этого файла безопасен: он обновляет те же правила доступа и настройки хранилища.

### 3. Создай свой аккаунт для админки и закрой регистрацию

1. В Supabase открой **Authentication** → **Users** и создай пользователя со своим email. Если выберешь приглашение, открой письмо и задай пароль.
2. Затем открой **Authentication** → **Sign In / Providers** → **Email** и отключи **Allow new users to sign up**.

Так в админку войдёт только заранее созданный пользователь. Вход находится на странице `admin.html`.

### 4. Скопируй два значения в файл сайта

В проекте Supabase нажми **Connect** и найди **Project URL** и **Publishable key**. Их также можно посмотреть в **Settings** → **API Keys**.

Открой файл `js/supabase-config.js` и замени только значения в этих двух строках:

```js
export const SUPABASE_URL='YOUR_SUPABASE_PROJECT_URL';
export const SUPABASE_PUBLISHABLE_KEY='YOUR_SUPABASE_PUBLISHABLE_KEY';
```

Например, Project URL начинается с `https://`, а Publishable key — с `sb_publishable_`. Если в старом интерфейсе отображается только ключ `anon`, можно использовать его как устаревший совместимый вариант.

**Не вставляй** `Secret key` (`sb_secret_...`) или `service_role`. Эти ключи дают полный доступ к базе и не должны попадать в браузерный код или GitHub. Для этого сайта нужен именно Publishable key; правила доступа уже задаются SQL-файлом.

### 5. Обнови сайт и проверь сохранение

Сохрани `js/supabase-config.js`, загрузи изменения проекта на GitHub Pages и открой локальную админку на том же компьютере и в том же браузере, где раньше добавлялись проекты. Войди, нажми «Изменить» у существующего проекта и затем «Сохранить проект» — это перенесёт весь текущий локальный каталог и его изображения в Supabase. После этого GitHub Pages будет показывать общие данные. Новые проекты и загруженные изображения тоже будут храниться в Supabase и появляться на сайте с любого устройства.

**Важно:** пока файл `js/supabase-config.js` заполнен настоящими значениями, сайт использует Supabase вместо локального хранилища этого браузера. Сначала проверь вход и сохранение на локальной копии, затем отправляй этот файл вместе с остальными изменениями на GitHub.
